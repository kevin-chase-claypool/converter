# Raise the pen-up dwell default to 1000 ms

## Summary

`pen_up_ms` now defaults to **1000 ms** instead of 800 ms. The converter's Pen
group shows `Pen up ms = 1000`, and the P115 recovery fallback dwell (`A`
argument) follows the same value.

## Reason

The operator asked for a 1000 ms pen-up dwell.

## Implementation

- `converter_core/settings.py`: `pen_up_ms = 1000.0`, the Pen group default
  string updated to `1000`, and the comment now records the choice (measured
  M5 clear time about 0.46 s plus margin).
- `gcode.py` needs no change: `pen_up_duration_ms()` reads the setting, so the
  fixed-dwell fallback emits `G4 P1.0` and the GP27 recover path emits
  `A1` instead of `A0.8`.

## Verification

- `python -m unittest discover -s software\tests` -> 318 tests pass.
- `rg pen_up_ms software/converter_core/settings.py` shows the core default
  and the UI default string both at 1000.
- `test_theta_feed.py`: the two GP27 handshake tests now expect the `A1`
  fallback that follows the 1000 ms pen-up dwell.

## Struggles and rejected approaches

None; the value is a single setting and the emit paths read it directly.

## Risks and follow-up

- Every pen-up transition is 200 ms longer than before; on a job with many
  M3/M5 cycles the estimate and the plot both grow slightly. Turn on
  **Keep pen down between fill trails** or **Connect sine rows** to reduce the
  cycle count if that matters.

## Files

- `software/converter_core/settings.py`: default value, UI default, comment.
- `software/README.md`: Pen group documentation.
